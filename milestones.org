* M41 — The stream API: insert out of order, sequence a chosen subset, take one at a time (dmd, 2026-09-15)
Design DECIDED in notes/stream-design.org (option one): =StreamSpec { Key, Body, Head, State, Step; head(c, &Body) -> Head; delta(c, &Head) -> Delta }=. =Step= is either a PRIMITIVE (=Add=, =Max=, =Min=, =And=, =Or=, =Last=, =First=, or a tuple of them) or =Serial<F, REST>= over a =Fold { step(c, S, D) -> S }= of real code. A primitive stream's =insert= sequences itself (blind combine, then blind snapshot, so the stored state is the post-step value) and has NO =sequence= circuit; a serial stream's =insert= is a pure insert and =sequence(c, keys: NonEmpty<Key, REST>)= reads =acc= ONCE (the one popeq, the one contention point, one-step-per-block worst case), folds =step= under the fold's guard, stages the post-step state per key, writes =acc= once. =take(c, key) -> (Body, State)= and =combine(c, delta)= exist on both. =ContentionFree= is a marker that follows from =Step: Primitive=. Layouts: primitive = bodies + one acc cell and one snapshot map per component; serial = heads, bodies, acc, staged. Builds on M40.

* M24 — MinoCrab as a library: the GHC-API model (dmd, 2026-08-27)
The identity shift, dmd's: "this is primarily a library like the GHC API"
(https://hackage.haskell.org/package/ghc). GHC ships its innards as an
importable library so the whole Haskell tooling ecosystem — HLS, hlint,
plugins — is built WITHOUT forking GHC. MinoCrab should be the same for
ZKIR: expose the innards so third parties write their own super-optimised
ZKIR gadgets and their own optimisation passes ("compiler rules à la
carte") as ordinary crates, never a fork.
MinoCrab starts CLOSER to this than GHC ever was, because it is
library-first by construction — the eDSL IS the API — and the crate split
already mirrors GHC's internal layering: minocrab/minocrab-std are the
surface language + prelude, minocrab-ir is the "Core" layer (IR builder +
passes), minocrab-zkir is codegen/serialization, minocrab-sim is analysis
(cost model, region profiler, verification harness). The work is deciding
which seams become SUPPORTED extension points, not building the library
from scratch.
Motivated by the AA-manager port (2026-08-27, notes/manager-port.org),
whose −41%-rows-vs-compactc came entirely from the lowering levers this
milestone wants to hand to others.

THE METHOD (dmd, 2026-08-27) — a PER-CONSTRUCT loop, not a bulk port, and
the payoff lands in the TYPE SYSTEM rather than in a Lean file in a drawer:
  1. MAP — find our eDSL syntax construct's counterpart in Compact's
     syntax. The corpus ports already ARE this mapping in practice: each
     MinoCrab circuit is a Compact construct rendered in the eDSL.
  2. FIND — locate the Agda proof(s) about that Compact construct. Because
     the CHECKED Agda is STATIC/TYPING semantics, the constructs that have
     proofs are the source-level ones (well-formedness, typing rules) —
     which is precisely why this method fits the Agda we actually have,
     where a bulk port would not.
  3. PORT + CONSTRAIN — port the proof to Lean (machine-checked), AND
     reflect its invariants into MinoCrab's Rust TYPE SYSTEM so the types
     CONSTRAIN use of the feature to what the proof covers. The Lean
     proof is the WHY; the Rust type is the always-on enforcement at
     every call site. This is CLAUDE.md's "compile errors over panics"
     with a PROOF behind the constraint, landing on M24's type-level
     surface. A typing rule maps onto a trait bound / a distinct type that
     does not unify / an inline-const assert — the same ladder the hard
     rule already ranks.
     THE FIT (dmd, 2026-08-27): the Rust types are NOT required to cover
     EXACTLY the set of values the Lean proof allows. The requirement is
     SOUNDNESS in one direction — the types must admit a SUBSET of what the
     proof allows (never a value the proof does not cover) — and within
     that, the MAXIMAL such subset the type system can express at
     reasonable cost. Sometimes the subset is the whole set and the two
     coincide; often the proof's boundary is value-dependent or
     non-structural and the type-level approximation is properly smaller.
     Both are acceptable; admitting MORE than the proof is not.
     THE BALANCE: pick a reasonable point between usability and typing
     strength, leaning towards CORRECTNESS over usability but WITHOUT
     abandoning usability. A constraint that requires a type-level
     contortion no user could reasonably write (or read) is a worse
     product than a slightly smaller admitted set expressed plainly —
     and where tightening to the proof's edge would make the feature
     unspellable in practice, stop short and record the gap (the shortfall
     is an honest entry for the LIMITATIONS DISCUSSION below, not a
     failure of the loop).
  The deliverable of each turn of the loop is thus TWO things: a checked
  Lean proof, and a type-system invariant that makes only proven-safe
  usage spellable (the maximal usable subset, per THE FIT above).

* M39 — Nonces, fee policy, and the administrator: unstick and batch (dmd, 2026-09-06)
dmd (2026-09-06): two abilities an administrator on the EVM side needs,
BOTH OPTIONAL per contract, currently being implemented in Compact by
sig-net; plus the earlier ask that an administrator set the gas price
rather than the user.
1. UNSTICK: a transaction that never mines at nonce n blocks n+1, n+2, …
   for the key. The administrator asks the MPC to sign a BLANK
   replacement at n — the key's own address, zero value, no calldata,
   21,000 gas — with a HIGHER, administrator-chosen fee.
2. BATCH: request circuits no longer choose a nonce (two concurrent
   provers race for "next nonce" and one proves an unminable tx). A
   request INSERTS the transaction-minus-nonce into a structure whose
   insert is WRITE-ONLY (a push, no shared read in the proof); a FLUSH
   circuit pulls N entries, reads the last used nonce ONCE, numbers them
   last+1 … last+N, writes last+N, and emits all N sign events in one
   transaction; the MPC signs and submits N consecutive txs. Contention
   moves from every prover to the flush.
Flagged at filing (to confirm against sig-net's contract): (a) the
request RECORD carries the nonce, so in the batched design the record and
its request id are created at FLUSH, not insert — the environment (who
may refund, how much) must be attached at insert and carried into the
record, or keyed by a requester-owned handle; (b) today's request circuit
also =popeq=s the Signet request counter, a second shared read that races
the same way — a contention-free insert must drop it or key the queue by
something the requester owns.
